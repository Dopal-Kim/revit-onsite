# Revit On-Site — 시공자 관점 화면 점검 (UX review)

- 점검일: 2026-11-04 03:15–03:35, Revit 2026.3 다크 테마, 활성 문서 `revit\shoring_demo_mcp.rvt` (사본). 원본은 열지 않음.
- 방법: 컴퓨터 사용(화면 캡처·마우스)으로 리본 탭 `Revit On-Site` 를 직접 보고 버튼 10개에 마우스를 올리고, "프로젝트 설정" 창(취소로 닫음)과 미구현 버튼 안내 창 1개("설치 검측")를 확인.
- 기준: `design\ui_spec.md` (§1 Revit 화면 규칙, §2 리본, §3 문구, §7 대화상자, §8 아이콘).
- 확인한 화면 17장: `revit\screens\ui_01_…png` ~ `ui_17_…png`.
- **하지 않은 것**: "구역·동바리 생성" 실행과 3D 확인(총괄 지시로 생략, 작업 세션 MCP와 겹치지 않게), 미구현 버튼 나머지 7개의 안내 창(같은 코드 경로로 보임, 미확인), Esc 키로 창 닫기(자동화 키 입력이 Revit에 닿지 않아 판정 불가).

## 높음

### H1. 아이콘이 Revit 아이콘처럼 보이지 않음 (색 사각형 + 한 글자)
- **화면**: 버튼마다 둥근 원색 사각형에 한글 한 글자("설", "생", "검", "타", "측", "판", "보", "승", "서", "4D"). 구조 탭과 나란히 보면 Revit은 평면 픽토그램(보·벽·기둥 모양)인데 우리 탭만 앱 배지처럼 튄다. 다크 리본에서 주황·초록·보라 원색이 특히 눈에 띔.
- **명세 기대**: §8 — Revit 기본 아이콘 계열(평면 단색 + 외곽선, 그림자 없음), `design\icons\<이름>_32.png`·`_dark.png` 2벌, 테마 바뀌면 교체.
- **고칠 점**: `design\icons\` 의 PNG로 교체(`LargeImage`/`Image`), 다크 테마용 이미지 연결.
- 스크린샷: `ui_01_리본_OnSite.png`, `ui_02_리본_구조탭_비교.png`

### H2. 미구현 버튼 8개가 정상 버튼처럼 눌리고, 개발자용 안내가 뜸
- **화면**: 설치 검측·타설 등록·센서·공시체·기상·해체 판정·대시보드·승인 기록·서류 출력·4D 타임라인 모두 활성(회색 아님). "설치 검측"을 누르면 TaskDialog: 큰 글자 `설치 검측 (02_InstallCheck)`, 본문 "다음 단계에서 들어갑니다. 지금은 '준비' 패널의 두 버튼이 동작합니다.", [닫기(C)].
- **명세 기대**: §1 — 쓸 수 없는 버튼은 회색(`IExternalCommandAvailability`). §3 — 문구는 시공자 말로, 내부 이름 노출 없음.
- **영향**: 10개 중 8개가 막힘 → 발표 데모에서 시공자가 누르면 흐름이 끊김. `02_InstallCheck` 같은 Dynamo 스크립트 이름은 시공자에게 의미 없음.
- **고칠 점**: 구현 전 버튼은 `AvailabilityClassName` 으로 회색 처리 + 툴팁 끝에 "(다음 버전)" 정도만. 안내창을 남긴다면 제목 = 버튼 이름, 본문 = "이 기능은 아직 준비 중입니다." 한 줄, 코드명 삭제.
- 스크린샷: `ui_15_미구현_안내창.png`, `ui_01_리본_OnSite.png`

### H3. 프로젝트 설정의 "착공일" 이 실제로는 첫 타설일·4D 시작일로 쓰임
- **화면**: 첫 칸 레이블 "착공일", 오른쪽 설명 "4D 자동 계획의 시작일".
- **명세 기대**: §7-1 — "첫 타설일". 현장에서 착공일(공사 시작)과 골조 첫 타설일은 몇 달 차이가 남.
- **영향**: 시공자가 계약 착공일을 넣으면 타설·해체 일정 전체가 그만큼 앞당겨져 계산됨 → 판정 기준일이 틀어질 위험.
- **고칠 점**: 레이블을 "첫 타설일"로, 설명을 "이 날부터 사이클대로 층별 타설일을 자동 계획합니다."로. 매개변수 이름 `PRJ_StartDate` 의미도 정의서에 맞춰 확인.
- 스크린샷: `ui_13_프로젝트설정_창.png`

## 중간

### M1. 툴팁이 한 단계뿐 — 긴 설명·F1 도움말 없음
- **화면**: 마우스를 6초 올려도 짧은 툴팁(제목 + 1–2문장)에서 더 펼쳐지지 않음. Revit 기본 버튼은 오래 올리면 긴 설명·그림·"F1 키를 누르면 도움말"로 확장됨.
- **명세 기대**: §1 — 모든 버튼에 `ToolTip`·`LongDescription`·`ToolTipImage`·`SetContextualHelp`. §3 — 긴 설명에 규정 근거와 "모델을 바꾸는지".
- **고칠 점**: 현재 툴팁 문장을 `LongDescription` 으로 옮기고, `ToolTip` 은 명세 §2 표의 한 문장으로. 특히 "구역·동바리 생성"은 긴 설명에 "다시 누르면 이전 생성분을 지웁니다(모델 변경)"를 둠.
- 스크린샷: `ui_03_툴팁_프로젝트설정.png` (6초 후), `ui_04`–`ui_12`

### M2. 버튼 글자의 줄바꿈이 툴팁 제목에 공백으로 들어감
- **화면**: 툴팁 제목 "대시 보드", "센서·공시체 ·기상".
- **명세 기대**: 제목 = 버튼 이름 그대로("대시보드").
- **고칠 점**: 버튼 `Text` 는 줄바꿈 포함, 툴팁 제목(`ToolTip` 제목은 Revit이 버튼 글자를 씀)이 어색하면 버튼 글자 자체를 줄바꿈 없이 짧게(M3).
- 스크린샷: `ui_09_툴팁_대시보드.png`, `ui_07_툴팁_센서공시체기상.png`

### M3. 버튼 글자 줄바꿈이 어색함
- **화면**: "센서·공시체 / ·기상" — 둘째 줄이 가운뎃점으로 시작. "대시 / 보드" — 한 단어가 쪼개짐. "해체 / 판정", "승인 / 기록" 처럼 한 줄에 들어갈 4자도 두 줄.
- **명세 기대**: §3 — 버튼 글자 ≤ 6자 한 줄 또는 4+4자 두 줄. 명사형. (Revit 구조 탭도 "보", "기둥", "슬래브"처럼 짧은 한 줄이 대부분.)
- **고칠 점**: "대시보드"(한 줄), "데이터 가져오기"는 분할 버튼으로(M4), 2–4자 이름은 한 줄.
- 스크린샷: `ui_01_리본_OnSite.png`

### M4. 패널 구성이 명세와 다름 (큰 버튼 10개만)
- **화면**: 패널 5개, 모두 큰 버튼. 작은 버튼 쌓기·분할 버튼·라디오 토글 없음. "센서·공시체·기상" 한 버튼, "서류 출력".
- **명세 기대**: §2 — 준비 패널 작은 버튼 3개(모델 진단·매개변수 연결·뷰·필터 준비), 타설·데이터 패널의 분할 버튼 "데이터 가져오기 ▾"(공정표·센서·공시체·기상), 판정 패널 라디오 "표시: 상태/강도/일정", 승인·보고 패널 "보고서".
- **영향**: 발표 자료·매뉴얼(명세 기준)과 화면 이름이 달라 시연 중 혼동. 시공자는 "모델 진단" 같은 첫 확인 도구를 찾을 수 없음.
- **고칠 점**: 명세 §2 이름으로 통일하거나, 명세를 현재 화면에 맞게 고침(총괄 결정). 최소한 "서류 출력"↔"보고서" 이름 하나로.
- 스크린샷: `ui_01_리본_OnSite.png`

### M5. 프로젝트 설정 창 형식이 Revit 대화상자 규칙과 다름

- **명세 기대**: §7 — WPF, Owner = Revit 창, 아래 [확인] [취소] + 왼쪽 [?], 단위는 칸 뒤("7 일", "3 개층", "5 °C"). §3 — 시공자 말.

- **고칠 점**: 버튼 이름 [확인]; 설명 열은 "타설 기록·센서·공시체 CSV가 있는 폴더" 같은 우리말, 근거는 [?] 도움말이나 툴팁으로. 태그는 "판정 기준 보기"(명세 §2 슬라이드아웃)에서만 보이게.

## 좋은 점 (유지)
- 탭 이름·패널 이름(준비 / 설치 검측 / 타설·데이터 / 판정 / 승인·보고)이 현장 순서이고 짧은 명사형 — Revit 패널 이름과 어울림.
- 설정 창이 다크 테마에서도 라이트 — Revit 모달 대화상자와 같은 동작(§7 실측과 일치). 창이 Revit 화면 가운데에 뜸.
- 모달 창이 열리면 리본 전체가 회색으로 바뀌는 Revit 기본 동작 정상(`ui_17`).
- 툴팁 문구에 결론 규칙("해체 승인 요청 가능" / "존치")이 지켜짐, 승인·해체 지시 문구 없음.
- 기본값이 미리 채워져 있음(사이클 7, 존치 3, 양생 5.0, 관측소 108).

## 점검 환경 메모 (다음 화면 점검 세션용)
- Claude 데스크톱 창이 "항상 위"로 Revit을 덮어 컴퓨터 사용 클릭·키가 Revit에 닿지 않았음. 스크린샷에서는 Claude 창이 안 보여 원인 파악이 어려움. 우회: PowerShell로 Claude 창 `SetWindowPos(HWND_NOTOPMOST)` → Revit `SetForegroundWindow` → `SetCursorPos`/`mouse_event` 로 클릭, 확인은 스크린샷 도구로. 키 입력(Esc)은 포커스가 Claude로 돌아가 실패 → 대화상자는 **버튼 클릭으로** 닫을 것.
- `open_application "Revit 2026"` 은 이미 실행 중이어도 **새 Revit 인스턴스를 띄움** — 쓰지 말 것(이번에 한 번 떴다가 정상 종료함).
- 대화상자를 연 채로 두면 작업 세션의 MCP 호출이 막힘 → 열면 캡처 후 즉시 닫기.
