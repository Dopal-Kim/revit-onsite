# ② 오류 검토 계획 — 빠르게, 적은 토큰으로 (총괄 11-05)

원칙: **글자로 확인할 수 있는 것은 글자로**(자동 시험 → API·파일 → MCP 읽기), **화면 캡처는 색·배치·포커스처럼 글자로 못 보는 것만**(점검 1회 5장 이내). 배포 1번 → 점검 1번 → 실패만 고치고 → 실패 항목만 다시.
ⓐ 기능 적합성 검사(`docs/impact_map.md` 2절)는 이 계획과 **별도로 병행** — 오류 검토는 "의도대로 도나", 적합성은 "그 결과물이 파장을 만드나".

## 층별 방법과 비용
| 층 | 도구 | 무엇 | 토큰 | 누가 |
|---|---|---|---|---|
| 1 자동 시험 | `python tools\run_all_checks.py` (Python 18종 + Engine/Field/WebExport.Check) | 계산·문구 바이트 일치, 자체 검사 | 점검마다 1줄 (~25줄) | 총괄 |
| 2 파일·API | 시연 폴더 생성물 grep, `GET /api/model` JSON, `tools\check_ifc.py`, 생성 HTML grep | 결과물 내용(검측요청서·층 표지·이력서·IFC·alerts) | 항목마다 1–3줄 | 총괄 또는 revit-ui |
| 3 MCP 읽기 | `revit\mcp\*.cs` (modified·zone_params·pane_state·model_summary) | 모델 매개변수·대시보드 상태·변경 여부 | JSON 몇 줄 | revit-ui |
| 4 UIA 글자 | `uia_lib.ps1 Show-In <창>` | 창 문구·버튼 유무·결과 창 줄 | 창마다 10–30줄 | revit-ui |
| 5 캡처 | 스크린샷 (≤ 5장) | 색·테마·겹침·포커스 | 장당 큼 | revit-ui |
보고 형식: 표 한 장 `| # | 항목 | 방법(층) | 기대 | 결과 | 통과/실패 |` — 통과는 한 줄, 실패만 근거(문구·값) 붙임.
