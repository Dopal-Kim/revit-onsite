- 평가: 성실성 30 · 창의성 40 · 적용가능성 30, 10분 발표 + Revit 라이브 데모, .rvt 제출.
- 발표 속 숫자는 모두 `docs/scenario_validation.md`(= `python shoring\scenarios.py` 출력)와 정의서 §3.2·§4 에서 가져온다. 리허설 날 스크립트를 다시 돌려 PASS 11 · FAIL 0 · 미실행 1 을 확인하고, 숫자가 바뀌었으면 슬라이드를 고친다.

### 3-0. 발표 전 준비 (발표 시작 10분 전)
1. Revit 2026 실행 → 데모 모델 사본 열기(15층 RC 30 × 18 m, 슬래브 210, 층고 3.0 m, 구역 90개). 리본 `Revit On-Site` 탭, 오른쪽에 대시보드, 3D 뷰 "Revit On-Site 검측".
2. **시연 데이터 폴더 만들기 = 아래 한 줄** (작업 폴더에서, 리허설 직전과 본 발표 직전에 한 번씩):
   ```powershell
   python tools\make_demo_data.py revit\onsite_data_demo
   ```
   샘플(9–12F zones·pours·sensors·cylinders) + "시연용" 설치검측(`install_inspection.csv`)·9F 작업계획서(`evidence.csv`) → 12-31 기준 9F 근거 3/8. 폴더에 있던 파일(11-04 점검 시험 `approvals.csv` 2건·`evidence.csv`·리허설의 `shore_checks.csv`·요청서 HTML 등)은 `_보관_YYYYMMDD_HHMMSS\` 로 옮겨지고 지워지지 않는다 — 그래서 승인 기록 사슬은 새로 시작하고 13F-A1 은 "타설 보류"에서 시작한다. [프로젝트 설정]의 데이터 폴더가 이 폴더인지 확인한다(회귀 기준 `shoring\sample\data` 를 가리키면 설정 창에 경고 줄 — 스크립트도 그 폴더는 거부).
3. **승인 단계는 9F-B1 로 시연 (메모)**: 모델의 9F-A1 구역 상태 6(감리 승인 기록, 11-04 점검 시험)은 `approvals.csv` 를 옮겨도 **모델에 남고** [판정]이 덮지 않는다(사람 기록 6·7·8 보호). 그래서 대본은 **9F-B1** 기준이다(같은 "해체 승인 요청 가능", 근거 3/8). 타설 전 확인도 같은 열 **13F-B1** 로 해서, 휴대폰 동바리 확인 3건(10F-B1·11F-B1·12F-B1)이 13F-B1 "타설 요청 가능"과 9F-B1 요청서 ① ✓ 를 한 번에 만든다. 칩 숫자는 9F-A1 이 처음부터 6 이라 시작 "해체 승인 요청 가능 3구역·감리 승인 기록 1구역" → 9F-B1 승인 기록 뒤 "2구역·2구역". 9F-A1 로 하려면 승인 기록 전에 저장한 모델 사본을 연다.
   - 리허설이 끝나면 **모델을 저장하지 않고 닫는다** — 저장하면 리허설에서 넣은 9F-B1 상태 6·7 도 모델에 남아 본 발표에서 같은 문제가 생긴다.
   - 알아 둘 것: 23:57 빌드부터 [승인 기록]·[근거 원장] 기본 시각 = 판정 기준일(데모 자료일 때, note "(시연 시각 — 판정 기준일 고정)") — 실제 시계 경고 없음, 근거 원장 날짜도 12-31 로 자동.
4. 휴대폰: 현장 PC 와 같은 Wi-Fi, [현장 입력]을 켜고 QR 로 미리 접속해 입력자 이름을 넣어 둔다(Windows 방화벽은 리허설 때 "개인 네트워크 허용"). 휴대폰 화면 위쪽에 "기준 시각 2026-12-31 09:00 (데모 고정)" 이 보이면 된다.
5. 브라우저 탭: 대체용 `web\onsite_4d_demo.html` (인터넷 불필요).
6. 대시보드 기준일 2026-12-31 로 [판정] 한 번 → 결과 창 확인 후 닫기(결과 창은 Revit 을 막지 않지만 화면을 가림). 시연 폴더를 새로 만든 뒤 첫 판정이라 zones.csv(샘플 9–12F)에 모델 구역(13–15F 포함)을 더했다는 줄이 한 번 뜬다 — 정상, 이게 있어야 13F-B1 타설 전 확인이 된다.

### 3-2. Revit 이 멈추면 (대체 경로)
1. 10초 기다린다 (구역·동바리 생성은 6초, 판정은 수 초). 응답 없음이 계속되면 Revit 을 건드리지 말고 바로 넘어간다 — 강제 종료하지 않는다 (재시작하면 MCP·애드인 상태 복구에 시간이 든다).
2. Alt+Tab → 미리 열어 둔 `web\onsite_4d_demo.html`.
3. 같은 이야기를 웹에서: 날짜 입력에 2026-12-31 → 9층 A2·B2 색과 클릭 시 판정 근거(23.90 < 24) → ▶ 재생으로 10/1 부터 해체 진행 → 경고 패널 "2026-12-28 에 동바리 6개층분이 동시에 필요" → 가정 목록(가상 벽·창호, 평년 기온) 한 번 보여 주기.
4. KBIM 높이 플래그는 웹 공유판에 없으므로 슬라이드 7 의 캡처(리허설 때 찍은 설치 검측 결과)로 보여 준다.

| 강도식 오차는? | 성숙도 보정곡선 ±10 % 관리(WisDOT), 그래서 공시체가 기준 근거이고 센서는 위치 근거로만 쓴다. 현장 공시체로 계수 s 를 역산해 보정한다(`calibrate_s`). |
| 최상층은 왜 3개층 규칙을 통과하나? | 3개층 존치는 위층 타설 하중 분담 목적이라 지붕 슬래브 위에는 타설이 없다는 팀 해석 [가정]. 강도(공시체) 기준은 그대로 요구한다 (S7). |
| 다른 모델에도 되나? | KBIM 10층 업무시설 IFC(그리드 없음, 한글 레벨명, 층고 4.1 m)로 범용성 시험, RAVA3Pro 프리캐스트 슬래브는 "동바리 대상 없음"이 나와야 하는 부정 시험(S10, Revit 에서 확인 예정). |
