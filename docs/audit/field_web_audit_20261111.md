# 현장 웹 실용성 점검 — 휴대폰·웹 화면 (2026-11-11, vercel 세션)

범위: `web/field/index.html`·`view.html` (= `server/vercel/pages` 같은 파일, Wi-Fi 서버 `tools/field_server.py` 도 같은 화면), `server/vercel/pages/supervisor.html`·`timeline.html`.
기준: `docs/guide/기능_구동체계_안내서.html` 휴대폰 기능 M-01–M-08, 「거푸집 및 동바리 해체 가이드라인」(국토부 2023.1) 3.2 해체 안전작업 절차·3.2.7 최종승인·3.3.3 감리 역할·4.1–4.3 체크리스트.
방법: 코드·CSS 읽기 + 로컬 시험 서버(dev.js)·Chrome 로 화면 확인. 재배포·환경 변수 변경 없음. 관점 ① 품질·안전관리자 ② 협력업체 반장 ③ 감리.

## 잘 된 점
1. 입력 화면이 장갑·햇빛을 고려함 — 버튼 52–60 px, 숫자 칸 28 px 숫자 키패드, [햇빛] 고대비, 이름·양생 방법 기억, 오류는 칸 아래 한국어 한 줄로 "무엇을 어떻게 고칠지" (서버 문구 = Python 판정 엔진 문구).
2. 망이 끊겨도 입력이 안 사라짐 — 입력 화면·신고 화면 모두 기기에 저장 → 연결되면 자동 재전송, client_id 로 두 번 저장 안 됨, 사진은 Vercel 에서 1600 px 로 줄여 보냄.
3. 반장 신고가 짧음 — 층 QR → 이름(처음 한 번) → 구역 버튼 1번 → 확인 창, 승인 기록 없는 '뺐음'은 즉시 빨강 띠·알림.

## 가장 큰 문제 5개
1. **반장 화면이 "해체 … 가능"으로 읽힘** — 상태 5 줄이 "해체 승인 요청 가능 — 감리 확인 전 해체 금지". 글을 끝까지 안 읽는 반장에게는 앞부분 '해체 … 가능'만 남는다 (#1).
2. **감리 확인이 가이드라인 두 번의 승인(3단계 작업계획서 승인 · 6단계 최종승인)을 체크 3개 한 번으로 합침** — 3.2.7 이 요구하는 작업준비·공구 점검·작업자 자격·안전교육 확인이 '③ 해체 전 체크리스트' 한 칸에 묻히고, 반려·보완 요청 길이 없다 (#11, #12).
3. **타설 전 동바리 확인(M-04)이 구역마다 한 건씩** — 6구역 층을 타설하려면 아래 3개층 18건을 따로 넣어야 해서 현장에서 생략되기 쉽다 (#5).
4. **지하·무신호에서 화면 자체가 안 열림** — 입력은 기기에 쌓이지만 화면(HTML)은 캐시되지 않아 한 번 닫으면 다시 못 연다. 지하층 공시체·동바리 점검이 바로 이 경우 (#8).
5. **Vercel 로 넣은 값이 판정에 반영되는 시점이 안 보임** — 저장 뒤 "판정은 Revit 동기화 뒤"만 나오고, 입력 화면에는 '마지막 동기화 n분 전'이 없다. PC·Revit 이 꺼져 있으면 감리 화면·층 표지 상태가 멈춰 있는데 아무도 모른다 (#9).
