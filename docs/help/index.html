처음 쓰는 순서 (역할별 하루 흐름)

Revit On-Site 는 슬래브 동바리를 언제 빼도 되는지 감리에게 승인 요청할 수 있는 상태인지를 층·구역별로 판정하고, 그 근거 서류를 Revit 안에서 만드는 도구입니다. 모든 버튼은 리본의 Revit On-Site 탭에 있고, 패널 순서가 현장 업무 순서입니다(준비 → 설치 검측 → 타설·데이터 → 판정 → 승인 → 보고·공유, 끝에 타임라인). 결과물은 모두 [프로젝트 설정]의 데이터 폴더에 남고, 파일 이름의 YYYYMMDD 는 마지막 판정 기준일입니다.

버튼에 마우스를 올려 두면 설명과 그림이 나오고, 그 상태에서 F1 을 누르면 이 페이지의 해당 항목이 열립니다. 한 장으로 인쇄해 현장에 두려면 빠른 시작 (A4 2쪽, 역할별).

프로젝트를 시작할 때 한 번 (공무·BIM 담당)

  1. Revit 옵션 › 색상 › 캔버스 테마 = 밝게 — 어두운 캔버스에서는 Revit 이 3D 색을 어둡게 바꿔 연노랑이 올리브처럼 보입니다(대시보드 칸 색과 같게 보려면 밝게).
  2. 준비 › 프로젝트 설정 — 첫 타설일(착공일 아님), 타설 사이클, 최소 존치 층수, 배합·fck, 양생 최저 온도, 기상 관측소, 데이터 폴더(사진 폴더 용량이 아래에 보임). 선택: 예측일에 현장 보정 쓰기.
  3. 준비 › 매개변수 연결 → 준비 › 뷰·필터 준비 — 검측용 매개변수와 상태 색 뷰.
  4. 모델을 열 때 구역이 없으면 구역 나누기 확인 창이 한 번 뜹니다 → [구역 나누기] (나중에는 준비 › 구역 나누기) — 매개변수 연결·설정 기본값·구역만(동바리 0)을 한 번에.
  5. 준비 › 모델 진단 — 층·슬래브를 제대로 인식했는지 먼저 봅니다(모델은 바뀌지 않음). IFC 로 가져온 모델이면 꼭.
  6. 동바리 › 예시로 채우기 (슬라이드아웃) — 층마다 구역(해체 단위)과 예시 동바리. 실제 동바리는 층 입력 뷰에서 직접 놓고 고칩니다 (v6). 결과 창 생성한 동바리 보기 = 이번에 만든 층의 동바리만 층마다 색·층별 본수로 보는 3D 뷰(뷰 설정만 바뀜).
  7. 날짜는 공정표 없이 직접 넣습니다 (v6): 동바리를 세운 날 동바리 › 동바리 사양(설치일 포함), 타설한 날 타설 등록.
  8. 층마다 동바리 설치 뒤 설치 검측 › 설치 검측 — 이음·높이·수평연결재·1본 하중을 한 번에. 설치 서류는 승인 › 근거 원장 1 설치검측.

  5. 창을 닫으면 서버가 꺼지고, 다음에 켤 때 주소의 토큰이 바뀝니다(옛 QR 은 쓸 수 없음). 닫고 입력 끄기 는 끄기 전에 확인을 묻습니다(기본 아니요 — 다른 프로그램에 치던 Enter 로 꺼지지 않게).
  6. 휴대폰 맨 위 오늘 볼 것: 무단 해체 의심 → 타설 보류 → 순찰 확인 없음(동바리가 서 있는 판정 구역에 순찰 확인 간격 [가정, 기본 24시간] 안 동바리 확인 기록이 없으면 층마다 한 줄 "9F 순찰 확인 없음 5구역 (… · 마지막 확인 n시간 전) — 구역 목록", 협력업체 신고는 안 셈) → 감리 확인 못 넣음(웹 서버 감리 직접 확인을 동기화 때 Revit 검사에서 넣지 못한 이유) → 시험 필요 → 상태 바뀜 → 입회 없음(판정일까지 타설했는데 pours.csv 의 supervisor_present·watcher 가 빈 구역 — 두 열이 없으면 세지 않음, KCS 14 20 12 3.2(11) 타설 중 감시자 배치 확정) 순서로 개수가 보이고, 누르면 목록·구역으로 갑니다(판정은 바꾸지 않음). 대시보드 맨 위에도 같은 한 줄이 나옵니다.

모델을 바꾸나요

예. 받은 값으로 구역·동바리의 판정 매개변수를 갱신하고, 센서는 SNS_Sensor 표식을 슬래브 윗면에 놓고 최근 값을 기록합니다. 실행 취소 목록에는 "Revit On-Site: 현장 입력 반영" 으로 남습니다. 원 자료는 데이터 폴더의 cylinders.csv·sensors.csv·sensor_strength.csv·rebound.csv·shore_checks.csv 에 입력자·시각과 함께 쌓입니다. 동바리 확인은 판정에 쓰이지 않아 모델을 바꾸지 않습니다(실행 취소 기록 없음). 휴대폰 구역 타일은 모델 구역과 같습니다 — 데이터 폴더 zones.csv 에 없는 모델 구역은 켤 때 끝에 더해집니다.

자주 나오는 안내 문구와 해결

  • 휴대폰에서 "접속 주소가 만료됐습니다 (12시간)" — 주소는 만든 뒤 12시간 동안만 열립니다 가정. PC 의 현장 입력 창에서 새 주소 를 누르고 새 QR 을 찍으세요. 서버를 다시 켰을 때도 새 QR 을 찍습니다.
  • 여러 네트워크(유선·Wi-Fi·VPN) — 창 위 목록에서 휴대폰과 같은 망의 주소를 고르면 그 주소로만 다시 켭니다("모든 망"은 0.0.0.0).
  • 휴대폰이 열리지 않음 — 같은 Wi-Fi 인지, 방화벽에서 개인 네트워크를 허용했는지 확인하세요. 창의 "다른 LAN 주소"를 써 볼 수 있습니다.
  • "같은 시각 값이 이미 있습니다" — 같은 센서·같은 시각은 한 번만 저장됩니다. 시각을 확인하세요.

현장 사진 (근거로 남김)

동바리 확인·해체 후 점검·협력업체 해체 신고에 사진 1장을 붙일 수 있습니다(선택). 사진 칸을 누르면 휴대폰 카메라가 열리고, 찍은 사진은 원본 그대로(바이트를 바꾸지 않음) 데이터 폴더 사진\YYYYMMDD\{구역}_{종류}_{시분초}_{해시 앞 8자}.jpg 에 저장됩니다 — 이름은 서버가 정합니다. 기록 줄의 photo 칸에 그 경로, photo_sha256 칸에 SHA-256 이 남아 슬래브 이력서 '현장 사진' 줄·검측 패키지 첨부\사진\(요청 구역 사진 + 검측요청서 현장 확인 ① 위 3개층 구역의 최근 24 h 동바리 확인 사진)·감사 기록(경로 · sha 앞 12자, 줄 해시)·근거 원장 7 해체(신고 사진)에 들어갑니다.

  • 받는 사진: JPEG·PNG, 8 MB 이하 가정. 종류는 파일 앞 바이트로 확인합니다 — 이름만 .jpg 인 다른 파일은 받지 않습니다.
  • 같은 날 같은 구역·종류에 같은 사진을 다시 보내면 새 파일을 만들지 않고 그 파일을 씁니다.
  • 전파가 약해 기기에 저장된 기록은 사진도 함께 담아 두지만, 기기에 담는 사진은 3장까지 가정(휴대폰 브라우저 저장 공간). 넘으면 "사진은 연결된 뒤 다시" — 화면을 연 동안은 사진도 함께 보내고, 화면을 닫으면 기록만 갑니다.
  • 설치 검측은 휴대폰 입력이 아니어서(install_inspection.csv) 사진은 근거 원장 1 설치검측 서류(파일 + SHA-256)로 붙입니다.

협력업체 해체 신고 (신고 QR)

동바리는 협력업체가 빼는데 그 사실이 기록에 잘 남지 않습니다. 현장 입력 창의 협력업체 해체 신고 QR (반장에게 따로)(접혀 있음)를 펼쳐 층을 고르면, 해체하는 반장에게 보여 줄 QR 이 나옵니다. 반장이 찍으면 층 표지의 층 화면과 같은 화면에 구역마다 이 구역 동바리를 뺐음·다시 세움 버튼과 이름(필수)·소속(선택) 칸이 붙습니다. 버튼을 누르고 확인 창에서 [확인]하면 shore_checks.csv 에 그 시각(서버 시각)·이름이 source = 협력업체 신고 로 한 줄 남습니다(소속은 company 열).

  • 감리 승인 기록 없이 '뺐음' → 반장 화면 "신고 저장됨 — 감리 승인 기록 없음: 현장 확인 요청됨", 대시보드·휴대폰 오늘 볼 것 맨 위에 무단 해체 의심(기존 규칙 그대로 — 아래층 동바리 '없음' 기록이라 그 위층 타설 전 확인에도 들어감).
  • 감리 승인 기록 뒤 '뺐음' → "신고 저장됨 — 감리 승인 기록 있음: 해체 시각 기록됨", 경고 없음. 근거 원장 7 해체에 실제 시각이 근거로 들어갑니다.
  • '다시 세움' → 동바리 확인 '예' 한 줄. 무단 해체 의심은 기존처럼 [승인 기록]의 '재받침' 기록 뒤 '예' 확인이 있어야 풀립니다.
  • 전파가 약한 곳(지하 등) — 보내지 못한 신고는 휴대폰에 "기기에만 저장 · 누른 시각" 으로 남고, 연결되면 자동으로 다시 보냅니다(같은 신고는 한 번만 저장). 기록 시각은 서버가 받은 시각이고, 누른 시각(휴대폰 시계)은 메모(note)에 "기기 시각 … (오프라인 저장 뒤 전송)" 으로 따로 남습니다 — 휴대폰 시계를 바꿔 시각을 앞당길 수 없게.

신고 주소는 신고 토큰(데이터 폴더 report_token.txt, 만료 없음)만 담고 있어 신고 말고는 저장할 수 없고, 층 표지 QR(보기 토큰)·입력 QR(입력 토큰)로는 신고가 안 됩니다. 신고 주소를 바꾸려면 report_token.txt 를 지우고 현장 입력을 다시 켭니다. 화면 문구는 신고 확인까지이며 해체를 지시하지 않습니다.

입력 형식 상세: 저장소 docs/field_input_spec.md.

서버 연동 CmdServerLink

현장 입력 패널 · 큰 버튼 (누를 때마다 켬·끔, 켜면 글자 '서버 연동 켬') · 쓸 수 있을 때: 프로젝트

툴팁현장 서버(인터넷)와 휴대폰 입력·판정을 주고받기를 켜고 끕니다.

무엇을 하나요

켜면 바로 한 번, 그 뒤 5분마다 가정: ① 현장 서버에 쌓인 휴대폰 입력을 가져와 데이터 폴더 CSV 에 넣고(현장 입력 과 같은 검사·같은 열·사진 저장, 같은 client_id 는 한 번만) ② 서버에 확인을 보내 다시 안 받게 하고 ③ 데이터 폴더로 다시 판정한 결과를 올립니다 — 휴대폰은 인터넷만 되면 같은 와이파이가 아니어도 됩니다. 받은 입력이 있으면 현장 입력과 같이 판정을 다시 계산해 구역 값·센서 표식·대시보드·강도 타임라인에 반영합니다. 통신은 뒤에서 하므로 Revit 을 기다리게 하지 않습니다.

서버는 판정하지 않습니다 — 휴대폰 저장 답은 "저장됨 — 판정은 Revit 동기화 뒤 반영"이고, 다음 동기화 뒤 휴대폰에 새 판정이 보입니다. 서버 검사 뒤 데이터 폴더가 바뀌어 받을 수 없게 된 입력은 거부하고 사유를 결과 창·대시보드 기록에 남깁니다(휴대폰엔 '저장됨'으로 남음). 파일이 Excel 등으로 잠겨 있으면 그 입력은 다음 동기화 때 다시 받습니다.

언제 쓰나요

현장 PC 와 휴대폰이 같은 와이파이에 없을 때(층이 높거나 PC 가 사무실에 있을 때). 지하·인터넷 없는 곳은 현장 입력(같은 와이파이)을 씁니다 — 둘을 같이 켜도 됩니다.

순서

  1. 처음 한 번: 서버를 만든 사람에게 받은 서버 주소·동기화 키·휴대폰 토큰을 Windows 사용자 환경 변수 FIELD_SERVER_URL · FIELD_SYNC_KEY · FIELD_TOKEN(입력) · FIELD_VIEW_TOKEN(층 보기) · FIELD_REPORT_TOKEN(협력업체 신고) 에 넣습니다. 동기화 키는 화면·기록 어디에도 보이지 않고, 휴대폰 토큰은 QR 과 QR 창 주소 글자에만 나옵니다 (기록·파일 이름에 안 씀).
  2. 타설·데이터 › 서버 연동. 휴대폰 QR 창(입력 QR + 층 고르기 → 층 보기·협력업체 신고 QR, 모두 서버 주소)이 뜨고, 첫 동기화 결과 창이 이어서 뜹니다 (가져옴: 저장·이미 있음·거부 / 올림: n개 층 판정). QR 창을 닫아도 연동은 계속됩니다.
  3. 켜진 채 다시 누르면 휴대폰 QR 보기 / 서버 연동 끄기 를 고릅니다. 연동 중 만든 층 표지 QR 도 서버 층 보기 주소입니다.

모델을 바꾸나요

받은 입력이 있을 때만: 구역·동바리 판정 값, 센서 표식 ("Revit On-Site: 서버 연동 반영" 실행 취소 1건). 데이터 폴더 CSV 에 줄을 더합니다.

판정 기준과 근거

해체 판정 과 같습니다. 계산은 tools/server_sync.py 와 같은 결과(C# 바이트 대조 시험 — RevitOnSite.Field.Check 5절).

자주 나오는 안내 문구와 해결

타설 등록 CmdPour

현장 입력 패널 · 큰 버튼 · 쓸 수 있을 때: 구역 있음

툴팁구역을 고르고 타설일·배합·fck 를 기록합니다.

무엇을 하나요

타설한 구역에 타설일·시각·배합·fck 를 데이터 폴더 pours.csv 에 한 줄씩 더합니다 — 휴대폰 현장 입력 과 같은 검사(없는 구역·이미 타설 기록이 있는 구역·미래 날짜·시각 HH:MM·배합·fck 18–60 MPa)이고, 여러 구역 중 하나라도 틀리면 아무것도 쓰지 않습니다. 판정 기준일이 있으면 그 시각으로 판정을 다시 계산합니다(상태가 양생 중 등으로 바뀜). 타설일은 강도 타임라인·웹 공유판의 추정 강도 시작점입니다.

타설 묶음(선택, 예: P-9F-1): 한 번에 같이 친 구역들에 같은 묶음 번호를 넣으면 공시체 결과를 묶음으로 한 번 넣어 묶음의 모든 구역에 씁니다(현장에서 공시체는 타설 로트마다 뜸). 같은 묶음은 같은 날·같은 배합·같은 fck 만 — 다르면 거절합니다.

언제 쓰나요

타설한 날(또는 다음 날 아침). 계획과 다른 날 타설했으면 반드시.

순서

  1. 타설·데이터 패널 › 타설 등록.
  2. 창의 구역 목록(타설 기록이 없는 구역, 층 순)에서 이번에 타설한 구역을 고릅니다(Ctrl·Shift 로 여러 개). 모델에서 구역을 먼저 고르고 누르면 미리 골라져 있습니다 — 구역 상자를 고르면 나오는 탭의 타설 등록 도 같은 창.
  3. 타설일(달력)·타설 시각(기본 08:00)·배합·fck 를 확인합니다(프로젝트 설정 값이 미리 채워짐). 입력자는 기록에 남습니다.
  4. 기록. 틀린 값이 있으면 창 아래 빨간 한 줄로 알리고 창은 그대로입니다. 결과 창에 기록한 구역과 판정 다시 계산 여부가 나옵니다.

모델을 바꾸나요

예 — 판정 기준일이 있으면 판정을 다시 계산해 구역·동바리 판정 값을 고칩니다(실행 취소 "Revit On-Site: 타설 등록" 한 번). 기록 자체는 데이터 폴더 pours.csv 입니다. 잘못 넣은 줄은 [구역 정보] 창의 [타설 기록 취소]·[공시체 기록 취소] (사유)로 지우고 다시 넣습니다 — 원래 줄은 파일에 남고 취소 줄이 덧붙습니다(추가만). 요청·승인 기록이 있는 구역의 타설은 취소할 수 없습니다.

1–3 모두 충족 → 해체 승인 요청 가능(연두). 하나라도 미달 → 존치(파랑 또는 주황) + 사유 + 예측 도달일. 공시체가 없으면 → 공시체 시험 필요(노랑): 센서만으로는 요청할 수 없습니다.

언제 쓰나요

매일 데이터를 넣은 뒤. 해체 검측요청서를 만들기 직전.

순서

  1. 판정 패널 › 해체 판정 (또는 대시보드의 판정).
  2. 기준일을 고릅니다(오늘 이 기본). 미래 날짜를 고르면 예측 판정입니다.
  3. 확인.
  4. 결과 창에서 "해체 승인 요청 가능" 구역 목록과 경고를 확인합니다.
  5. 구역을 골라 판정 근거 로 사유를 봅니다.

하중 비교에 쓰는 슬래브 두께는 zones.csv 의 slab_mm 열입니다. [판정] 때 모델에서 구역 평면과 겹치는 그 층 구조 슬래브 두께(최댓값)를 읽어, 열이 없으면 열을 더하고 빈칸만 채웁니다(있는 값은 그대로). 못 찾으면 빈칸 → 210 mm 가정. 판정 사유에 "슬래브 n mm (모델)" 처럼 출처가 붙습니다.

언제 쓰나요

매일. 현장 회의나 감리 협의 때 화면에 띄워 둡니다.

순서

  1. 판정 패널 › 대시보드. 오른쪽(특성 창 옆)에 창이 열립니다.
  2. 칸을 한 번 누르면 모델에서 그 구역이 선택·확대됩니다.
  3. 칸을 두 번 누르면 그 구역의 판정 근거(판정·예측 해체일·사유·판정 규칙 근거 한 줄 — 휴대폰 구역 카드에도 같은 줄), 판넬 조기 탈형, 한중 초기양생 경고(있을 때), 입력 점검 경고(pours.csv fck 가 프로젝트 기본 fck 와 다름 · 판정에 쓰는 공시체 3개의 범위가 평균의 15 % 를 넘음 가정 — 경고만, 판정은 그대로), 무단 해체 관측(감리 승인 기록 없이 동바리 없음 — 확인 필요), 타설 전 확인, 근거 n/8 이 열립니다.
  4. 다시 누르면 창이 닫힙니다.

버튼은 키보드(Tab → Space/Enter)와 화면 읽기 프로그램으로도 누를 수 있습니다. 마우스로 누르면 처리 뒤 키보드 포커스가 Revit 뷰로 돌아가 단축키를 그대로 쓸 수 있습니다.

판넬 조기 탈형 (칸 두 번 누르기)

슬래브 거푸집 판넬만 먼저 떼고 필러 동바리는 남기는 단계(매 사이클 타설 3–4일 뒤 결정)를 따로 보여 줍니다. 판정표·판정 근거 창 '판넬 조기 탈형' 줄은 강도 ①만 봅니다: 구역 최소 추정 강도와 현장양생 공시체(있으면) 중 낮은 값이 14 MPa 이상이면 "14 MPa 도달 — 판넬 조기 탈형 4조건 검토 대상", 아니면 "14 MPa 미달 — 판넬 존치" 확정 정의서 §3.2, 가이드라인(구조계산 + 14 MPa 이상). "판넬 탈형 요청 가능 (필러 존치)"은 아래 '판넬 단계' 줄의 4조건(① 14 MPa ② 10 ℃ 이상 4일 ③ 위층 하중비 ≤ 1.0 ④ 구조검토서 기록)을 모두 갖췄을 때만 나옵니다. 동바리 해체 판정과는 별개입니다.

② 10 ℃ 이상 4일의 온도 (v6.2): 구역 3 m 안 온도 센서의 날마다 평균(센서가 여럿이면 낮은 값)을 먼저 쓰고, 센서 기록이 없는 날만 기상 자료(weather.csv) → 평년 기온 가정 순입니다. 센서 날은 실측이라 양생 최저 온도(보온 가정)를 더하지 않습니다 — 가열 보양 현장은 센서를 달면 실제 양생 온도로 셉니다. 근거 줄 끝에 "(온도: 센서 S1·S2 일평균)"처럼 출처가 붙고, 벽·기둥 측면 무시험 일수의 평균기온도 같은 규칙입니다.

근거 n/8 (칸 두 번 누르기)

근거 줄 끝에는 타설 입회가 붙습니다: pours.csv 에 supervisor_present(예/아니오)·watcher(이름) 열이 있으면 그 구역 기록이 빈 경우 "입회: 타설 입회 기록 없음 — …", 두 열이 없으면 "참고: 타설 입회 — pours.csv 에 supervisor_present·watcher 열을 넣으면 점검합니다". 판정은 바꾸지 않습니다.

마지막 판정일(없으면 오늘)까지 그 구역이 갖춘 해체 절차 서류 단계입니다. 예: "근거 연속 3/8 (12-31 기준) · 갖춘 단계: 1 설치검측 11-23 · 2 작업계획서 12-20 · 3 공시체 12-30 · 5 검측요청 12-31". 연속 n = 1 부터 빈칸 없이 이어진 마지막 단계(위 예는 4 해체전점검이 없어 3). 순서가 빠지면 "경고: 해체(12-31) 전에 감리확인 기록 없음" 처럼 한 줄 더 나옵니다. 서류는 근거 원장 에서 넣습니다.

타설 전 확인 (칸 두 번 누르기)

이름: 휴대폰에서 넣는 것은 동바리 확인(입력, shore_checks.csv), 대시보드에서 보는 것은 타설 전 확인(결과)입니다.

그 구역을 지금 타설하려 할 때 아래 3개층에서 평면이 겹치는 구역마다 동바리가 서 있는지 봅니다. 기준 시각은 마지막 판정일 09:00 입니다.

  • ○ = 최근 24시간 안에 휴대폰 동바리 확인 "예" 가 있음. ✕ = 확인 없음·24시간 넘음·"아니오" 기록·해체 완료 기록(재받침 기록 없이는 지지 안 됨).
  • 모두 ○ 이면 "타설 요청 가능", 하나라도 ✕ 이면 "타설 보류" 와 구역별 사유. 이미 타설된 구역은 "이미 타설됨".

근거 원장 CmdEvidence

승인 패널 · 큰 버튼 · 쓸 수 있을 때: 구역 있음

툴팁고른 구역에 해체 절차 서류(작업계획서·해체전점검·결과보고 등)를 기록합니다.

무엇을 하나요

해체 절차 8단계 — 1 설치검측 · 2 작업계획서 · 3 공시체 · 4 해체전점검 · 5 검측요청 · 6 감리확인 · 7 해체 · 8 결과보고 — 의 서류를 구역·날짜에 묶어 "그날 어느 구역이 어느 근거까지 갖췄나"를 봅니다. 모델은 서명 원본이 아니라 위치·시점 색인입니다: 원본은 서명된 서류이고, 원장에는 파일 경로와 SHA-256 만 남아 파일을 바꾸면 값이 달라져 드러납니다.

사람이 넣는 단계는 주로 2·4·8 입니다. 나머지는 자동으로 읽습니다: 3 = 현장양생 공시체 결과(시험일), 5·6·7 = 승인 기록 의 요청 제출·감리 승인 기록·해체 완료(기록 사슬이 손상되면 쓰지 않음), 1 = 데이터 폴더에 설치검측표(install_inspection.csv)가 있으면 구역의 모든 항목이 OK 인 마지막 날.

무단 해체 관측 경고: 어떤 구역에 '동바리 없음' 관측(휴대폰 동바리 확인 '아니오' 또는 승인 기록 해체 완료)이 들어왔는데 그 시각까지 그 구역의 감리 승인 기록이 없으면 "승인 기록 없이 동바리 없음 관측 — 구역 MM-dd HH:mm 입력자" 경고가 남습니다. 대시보드 칸 경고·근거 줄, 휴대폰 구역 카드, 검측요청서 현장 확인 표 ①("⚠ 무단 해체 의심 — 확인 필요"), 층 표지 상태 줄(빨강)에 보입니다. 그 뒤 재받침 기록 다음에 '예' 확인이 들어오면 사라집니다. 판정·결론은 바꾸지 않는 경고이고, 사실 확인은 현장에서 합니다 (화정 2022: 하부 3개층 동바리가 승인 없이 빠진 채 타설).

순서

  4. 추가. 기록 번호(E0001…)·파일 SHA-256·갖춘 근거·순서 경고가 표시됩니다.

대시보드 아래 날짜 슬라이더를 움직이거나 ▶ 재생하면 "Revit On-Site 강도 타임라인" 3D 뷰의 구역 상자가 그날 추정 강도 색(추정 ÷ 그 층 fck — 40·60·80·100 % 구간, [표시: 강도]와 같은 색 가정)으로 바뀌고, 타설 전 구역은 흐린 회색입니다. 동바리·벽 등 나머지 부재는 모델 그대로이고(해체 애니메이션 없음), 그 층 실제 슬래브만 구역 상자가 대신 보여 줍니다. 예전 '4D 미리보기' 뷰(시공 순서용)는 활성 뷰가 아니면 지워집니다.

강도 예측 그림(막대 아래): 회색 선 = 층별 추정 강도(그 층에서 그날까지 타설된 구역 중 가장 낮은 값), 가로 파선 = 기준선 5 MPa 측면 거푸집 · 14 MPa 지지 슬래브 · fck 확정, 빨간 세로선 = 지금 날짜, 점 = 위 4개층의 그날 값, ◆ = 그날까지의 현장양생 공시체 실측(초록 = fck 이상, 누르면 그날로). 위 한 줄 = "추정 강도 (참고 · 판정에 안 씀) 12F 8.3 · 11F 15.2 … MPa — 그날 사건". |◀ 사건 사건 ▶| = 층 첫 타설 · 층 추정이 14 MPa·fck 에 처음 닿는 날(그 층 구역이 다 타설된 뒤, 참고) · 공시체 시험 날.

추정은 참고입니다. 판정의 예측 해체 가능일과 같은 식(타설일부터 날마다, 기온 = 데이터 폴더 기상 자료 또는 평년 가정, 양생 하한·층 높이 보정 = [프로젝트 설정])이고, 기간 = 첫 타설 ~ 마지막 타설 + 56일 가정. 해체 판정은 현장양생 공시체와 구역 3 m 안 센서 실측으로만 합니다(해체 판정). 계산은 shoring/strength_timeline.py (C# 바이트 동일). 웹 공유판 도 같은 곡선·색을 씁니다.

막대 아래 색 을 근거 단계 (1–8) 로 바꾸면 타설된 구역 색이 근거 원장 의 갖춘 단계로 바뀝니다: 1 설치검측부터 빈칸 없이 갖춘 마지막 단계, 회색 0 → 진녹색 8. 그날 넣은 서류는 다음 날부터 셉니다. 웹 공유판의 [색] 과 같은 규칙입니다.

색 을 동바리 상태 (검측 뷰) 로 바꾸면 "Revit On-Site 검측" 3D 뷰가 열리고, 뷰에 보이는 동바리가 마지막 판정 시각의 기록 기준 상태로 칠해집니다(화면 덧그림 — 모델·뷰 설정·실행 취소 목록은 그대로): 진회색 = 서 있어야 함(존치·공시체 시험 필요·타설 전) · 노랑 = 해체 승인 요청 가능 · 초록 = 감리 승인 기록 · 회색 윤곽 = 해체됨(해체 완료 기록·협력업체 해체 신고) · 빨강 굵게 + 깜빡임 = 무단 해체 의심(승인 기록 없이 동바리 없음 관측). 구역 테두리 주황 = 설치 검측 필요(기록 없음)·빨강 = 설치 검측 NG, 점선 = 다음 타설 층 아래 확인 대상인데 최근 24 h 동바리 확인 없음 가정 색. 타임라인 재생 중엔 깜빡임을 멈춥니다. 판정·결론은 바꾸지 않습니다. 계산은 shoring/shore_status.py (C# 바이트 동일).
