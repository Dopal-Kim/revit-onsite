IfcGrid와 IfcGridAxis가 **없다**. Revit 2017 내보내기에서 그리드를 빼고 내보낸 것으로 보인다. 그리드 대신 쓸 수 있도록 **콘크리트 기둥의 형상 중심을 군집**해 보았다(허용 오차 100–300 mm).

## 7. 층별 평면 범위 [추정 — 방법과 정확도]

**방법.** IfcLocalPlacement 사슬을 끝까지 합성한다(IfcAxis2Placement3D의 Location·Axis·RefDirection, 2D 배치, IfcMappedItem의 MappingOrigin과 변환 연산자). 그다음 Body 표현에서 다음을 처리한다.
- IfcExtrudedAreaSolid: 단면(사각형, 임의 다각형, 구멍 있는 다각형, IfcCompositeCurve, 원호 IfcTrimmedCurve는 9점 표본)을 세계 좌표로 옮기고 돌출 방향·깊이로 3D 범위를 구한다.
- IfcBooleanClippingResult: 첫 피연산자만 쓴다(잘리기 전 범위 = 상한값).
- IfcFacetedBrep / IfcFaceBasedSurfaceModel: 모든 꼭짓점을 쓴다.

## 8. 애드인 권장 사항

### 8.1 구조 바닥 슬래브 고르기 (이름에 기대지 않음)
이 도구에서 검증한 규칙이다. 326개 중 104개를 고르고, 기준층마다 정확히 구조 SL110 7개가 나온다.
1. 분류: IfcSlab(또는 Revit 바닥 카테고리)이고 PredefinedType이 FLOOR 또는 ROOF. LANDING(계단참)과 BASESLAB(기초)은 뺀다.
2. 재료: **가장 두꺼운 재료층이 콘크리트**이고 그 층 두께가 120 mm 이상. 이것으로 80/90 mm 마감과 100 mm 무근 토핑이 빠진다. 재료층이 없으면 전체 두께와 재료를 쓴다.
3. 고도: 슬래브 **상단이 어느 레벨 고도 ±300 mm 안**에 있을 것. 이것으로 1층 캐노피 지붕(+3,200)과 계단참이 빠진다. 화장실 내림(−50)은 남는다.
4. 층 지정은 포함 관계보다 **상단 고도로 가장 가까운 레벨**을 우선한다. 포함 관계와 고도가 어긋나는 슬래브가 56개다(대부분 계단참이 아래층에 속한 경우와 1층에 속한 지하 램프·드라이에어리어 슬래브).

Revit에서는 IfcPredefinedType과 재료층이 그대로 남는지 [미확인]이다. 남지 않으면 대체 신호로 2를 "바닥 카테고리 + BoundingBox 두께 120–400 mm + 재료명"으로, 3을 "BoundingBox 상단 ≈ 레벨 고도"로 바꾼다.

### 8.2 층과 동바리 받침층
- 층 = 레벨을 고도순으로 정렬한 것. 단 **구조 슬래브가 있는 레벨만** 타설층으로 본다. GL(−150)처럼 슬래브 없는 레벨은 건너뛴다.
- k층 슬래브의 동바리는 "**k층 아래에 있는, 구조 슬래브가 있는 가장 가까운 레벨**" 위에 선다. 1층 슬래브는 GL이 아니라 지하1층(−6,100) 위에 선다.
- 동바리 높이 = 레벨 차 − 슬래브 두께:

| 받치는 슬래브 | 동바리 높이 |
|---|---|
| 기준층 | 4,100 − 150 = **3,950 mm** |
| 2층 | 4,800 − 150 = 4,650 mm |
| 1층 | 6,100 − 200 = 5,900 mm |
| 옥탑층 | 5,000 − 150 = 4,850 mm |

  보 아래 동바리는 보 춤(400–850)만큼 더 짧다.
- 이 높이들은 흔히 쓰는 파이프서포트 길이를 넘을 수 있다. 높이별 수평연결재 규정이나 시스템 동바리 전환 기준은 정의서 §3.2 원문으로 확인해야 한다 [미확인].
- `SLAB_T_MM = 210` 상수는 이 모델에서 틀린다(150/200). 슬래브마다 두께를 읽어야 한다.

### 8.3 구역 나누기 (우선순위)
1. **Revit 그리드가 있으면** 그리드 칸으로 나눈다. 이름 대신 방향(곡선 방향 벡터)과 위치로 정렬한다.
2. **그리드가 없으면 (이 모델)** 받침층 콘크리트 기둥 BoundingBox 중심을 300 mm 오차로 군집한다. 기둥이 4개 이상 늘어선 열이 슬래브 외곽에서 1.5 m보다 안쪽에 있으면 절단선으로 쓴다. 기준층 결과는 X {13,000, 27,000}, Y {12,000, 19,300} → **3 × 3 = 9구역**이다(1.2 m 격자 기준 본수).

   | | Y −100–12,000 | 12,000–19,300 | 19,300–35,100 |
   |---|---|---|---|
   | X −100–13,000 | A1 109 | A2 66 | A3 142 |
   | 13,000–27,000 | B1 118 | B2 51 | B3 71 |
   | 27,000–37,300 | C1 80 | C2 48 | C3 64 |

   지하1층·1층은 기둥 열이 많아 22–25칸이 나오고 1–2본짜리 칸도 생긴다. **본수가 기준값(예: 30본) 미만인 칸은 이웃 칸에 합치는** 단계가 필요하다(아직 구현 안 함).
3. 기둥도 없으면 RC 벽 중심선 군집 → 그래도 없으면 고정 크기 타일(예: 10 × 9 m, 현재 데모 A1–C2 크기)을 슬래브 다각형으로 잘라 쓴다.
4. 대안: 모델의 **구조 슬래브 요소 자체를 구역으로** 쓴다. 기준층 SL110 7개는 496 / 334 / 122 / 97 m² 큰 판 4개와 작은 판 3개다. 타설 구획과 맞을 가능성이 있다 [추정]. 크기 차이가 커서 해체 단위로는 1번(기둥 칸)이 낫다.
5. 세대별 구역: 이 모델은 사무소라 **적용할 수 없다**. 공동주택 모델이 들어오면 IfcSpace나 Revit 룸 경계로 다시 검토한다.

### 8.4 1.2 m × 1.2 m 동바리 요소 수
- 기준층마다 약 **749본**(상한값)이다. 기둥 21개와 코어벽 아래를 빼면 약 720–740본으로 예상된다 [추정].
- 3개층 존치 ≈ 2,250본, 겨울 5개층 ≈ 3,750본이다. 데모 가정(416 / 1,248 / 2,080)의 1.8배다. 상세 동바리는 데모 1–2개층만 두고 나머지는 구역 상자로 두는 §3.5 방침을 유지해야 한다. FamilyInstance를 하나씩 만드는 생성 시간도 Revit에서 재 봐야 한다 [미확인].

### 8.6 Revit 2026 "IFC 열기(Open IFC)" 예상 매핑 — 모두 [미확인]
Revit 2026의 IFC 열기는 Autodesk 오픈소스 IFC 가져오기(revit-ifc)를 쓰는 것으로 알고 있고, 요소는 대부분 **DirectShape**로 만들어질 것으로 예상한다. 아래는 예상일 뿐이고 Revit에서 확인해야 한다.

| IFC | 예상 Revit 카테고리 | 애드인 영향 |
|---|---|---|
| IfcBuildingStorey 16 | 레벨(이름·고도 유지: `지상 1층` 등) | 층 판별은 고도순 |
| IfcSlab FLOOR / LANDING / BASESLAB | 바닥(Floors) DirectShape. LANDING은 계단 쪽일 수도 있음, BASESLAB은 구조 기초일 수도 있음 | `Floor` 클래스로 걸러지지 않음 → `OfCategory(OST_Floors)` + DirectShape 허용. 두께 매개변수 없음 → BoundingBox |
| IfcRoof + 하위 IfcSlab ROOF | 지붕(Roofs) | 구조 슬래브 후보에서 빠짐(여기서는 캐노피라 문제 없음) |
| IfcWall / IfcWallStandardCase | 벽(Walls) DirectShape | 재료층 정보 유지 여부 확인 필요 |
| IfcColumn | 기둥 또는 구조 기둥 | 구조 해석 모델 생성 여부, 위치는 BoundingBox 중심 |
| IfcBeam | 구조 프레임 | 보 아래 동바리 높이 계산에 BoundingBox 하단 사용 |
| IfcStair / IfcStairFlight / IfcRailing | 계단 / 계단(또는 일반 모델) / 난간 | 4D 계단 양생 표시 |
| IfcDoor / IfcWindow | 문 / 창 | 4D 창호 단계 |
| IfcCurtainWall / IfcPlate / IfcMember | 커튼월 패널·멀리언(또는 일반 모델) | 요소 약 12,000개, 뷰 성능 주의 |
| IfcSpace | 룸 또는 공간이 아니라 DirectShape나 숨김일 수 있음 | 구역 근거로 쓰기 어려움 |
| IfcOpeningElement | 만들지 않음(형상에 이미 반영) | — |
| IfcBuildingElementProxy / IfcCovering / IfcFurnishingElement / IfcFlowTerminal | 일반 모델 / 천장 등 / 가구 / 설비 | SHR_GenBy 삭제 로직이 일반 모델 카테고리를 훑을 때 섞임. 태그가 있어 안전하지만 성능에 영향 |

- IFC 속성(IfcGUID, Pset_SlabCommon, BaseQuantities 등)은 인스턴스 매개변수로 들어올 것으로 예상한다. 이름 형식(예: `LoadBearing`, `IfcPredefinedType`)은 Revit에서 확인해야 한다.
- DirectShape 바닥에 공유 매개변수(SHR_*)가 붙는지(카테고리 바인딩)도 확인해야 한다.
- 원본은 건드리지 않고 `revit\test_models\` 사본에서 열어야 한다(정의서 §3.7-1).

## 9. 파서 검증
- 문 단위 분해: 파일은 ';' 문 단위로 스트리밍한다(따옴표 안 ';'·여러 줄 문·한 줄 여러 문·주석 처리, `--selftest`로 확인). 파서 개체 수 **2,089,559** = 줄 단위 정규식 `^#\d+= TYPE(` 개수 2,089,559이고, 형식별 차이는 0이다. 이 파일은 한 줄에 한 문이라 두 방법이 같아야 정상이다.
- 고도: 층 Elevation과 배치 사슬 Z가 일치한다. 기준층 층고 4.1 m는 사무소 층고로 그럴듯하다(공동주택 2.8–3.0 m 범위는 아님 → §0).
- 범위: 기둥 중심이 슬래브 외곽 안에 있다. 단면 면적이 BaseQuantities와 맞는다(265/271, 2% 이내).
- 확인하지 않은 것: Revit 실제 가져오기 결과(§8.6 전부), 잘린 슬래브 7개의 실제 외곽, 보·기둥 아래 동바리 제외 후 본수, 구역 합치기 규칙.
