## 1. 핵심 문장
층간소음(사용성)과 붕괴(안전)는 같은 뿌리, **슬래브 구조체 품질**에서 나온다. 그 품질은 **타설·양생 단계**에서 정해지지만, 지금 현장은 날짜 사이클과 서류로 관리해 실제 구조체 상태가 보이지 않는다.

## 3. 논리 구조
문제(부실시공 → 층간소음 분쟁 + 붕괴) → 근본 원인(타설·양생을 강도가 아니라 날짜 사이클로 관리) → 왜 안 보이나(표준양생 합격 ≠ 현장 강도, 공시체 값이 위치·판단과 연결 안 됨, 센서는 BIM 매핑 없음) → 해결(Revit On-Site: 층·구역별 타설·온도·공시체·센서를 BIM에 연결해 "해체 승인 요청 가능 / 존치" 판정 + 근거) → 결과(조기 해체 차단, 구역별 양생 이력, 감리 승인 근거, 하자 분쟁 대응 자료)

## 5. 착안할 방향성 (각 세션 작업 기준)
1. **서사**: 층간소음은 동기·규모, 직접 근거는 구조 안전 + 슬래브 물성 연구. 단정 금지.
2. **데이터 축**: 현장양생공시체(기준 근거) 1순위, 센서는 위치 근거 보조 — 현 판정 우선순위 유지.
3. **겨울 공정을 데모 핵심으로**: 가이드라인 최소 3개 층 존치가 겨울에 부족함(엔진 계산) + 화정 사례.
4. **층간소음 연결은 확장 기능**: 구역별 양생 이력·해체일을 "슬래브 품질 기록"으로 남겨 사후확인·분쟁 증빙 — 발표에서 확장 방향으로만.
   - 현재 내보낼 수 있는 것(Revit 작업 세션 확인 11-04): 타설일·온도/강도 센서·공시체·반발경도(데이터 폴더 CSV, 현장 입력분은 입력자·시각·기기 기록), 구역 매개변수(타설일·추정/공시체 강도·판정·사유·예측 해체일·마지막 판정일), 웹 공유판 JSON(날짜별 구역 판정 + measurements[]).
   - 아직 없는 것: 감리 승인일·실제 해체일 — [승인 기록] 버튼 준비 중. 발표에서는 "승인·해체 기록은 다음 단계"로 말한다.
5. **검단 권고를 제품 존재 이유로 인용**: 검측 자료 디지털화·BIM 활용.
