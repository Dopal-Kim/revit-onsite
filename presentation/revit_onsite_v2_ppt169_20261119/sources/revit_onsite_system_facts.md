# Revit On-Site 시스템 자료 (프로젝트 문서 발췌)

출처: build-up-2/docs/help/index.html (Revit On-Site 도움말), revit/RevitOnSite/RevitOnSite/ServerLink.cs 머리 주석

## 도움말 — 개요·역할
Revit On-Site 는 슬래브 동바리를 언제 빼도 되는지 감리에게 승인 요청할 수 있는 상태인지 를 층·구역별로 판정하고, 그 근거 서류를 Revit 안에서 만드는 도구입니다. 모든 버튼은 리본의 Revit On-Site 탭에 있고, 패널 순서가 현장 업무 순서입니다(준비 → 설치 검측 → 타설·데이터 → 판정 → 승인 → 보고·공유, 끝에 타임라인). 결과물은 모두 [프로젝트 설정]의 데이터 폴더 에 남고, 파일 이름의 YYYYMMDD 는 마지막 판정 기준일입니다. 
 버튼에 마우스를 올려 두면 설명과 그림이 나오고, 그 상태에서 F1 을 누르면 이 페이지의 해당 항목이 열립니다. 한 장으로 인쇄해 현장에 두려면 빠른 시작 (A4 2쪽, 역할별) . 
 누가 무엇을 쓰나요 — 세 갈래 
 역할 쓰는 곳 하는 일 
 공무·BIM 담당 Revit — 리본 Revit On-Site 탭, 하루 1회 아침 판정, 검측요청서·검측 패키지, 승인 기록, 현장 입력 켜기 
 품질·안전관리자 휴대폰 — 타설·데이터 › 현장 입력 창의 [현장 입력] 탭 QR (12시간 가정 뒤 [새 주소]) 공시체·센서·반발경도·동바리 확인·해체 후 점검 입력, 동바리 점검 (단계별 항목 OK/NG·문제 동바리를 평면에서 고름), 사진 1장 
 협력업체 반장 휴대폰 — 같은 창의 [협력업체 신고] 탭 QR (층마다, 만료 없음) · 층 표지 QR(보기 전용) 구역마다 [이 구역 동바리를 뺐음]·[다시 세움] 신고, 사진 1장 
 프로젝트를 시작할 때 한 번 (공무·BIM 담당) 
 Revit 옵션 › 색상 › 캔버스 테마 = 밝게 — 어두운 캔버스에서는 Revit 이 3D 색을 어둡게 바꿔 연노랑이 올리브처럼 보입니다(대시보드 칸 색과 같게 보려면 밝게). 
 준비 › 프로젝트 설정 — 첫 타설일 (착공일 아님), 타설 사이클, 최소 존치 층수, 배합·fck, 양생 최저 온도, 기상 관측소, 데이터 폴더 (사진 폴더 용량이 아래에 보임). 선택: 예측일에 현장 보정 쓰기. 
 준비 › 매개변수 연결 → 준비 › 뷰·필터 준비 — 검측용 매개변수와 상태 색 뷰. 
 모델을 열 때 구역이 없으면 구역 나누기 확인 창이 한 번 뜹니다 → [구역 나누기] (나중에는 준비 › 구역 나누기 ) — 매개변수 연결·설정 기본값·구역만(동바리 0)을 한 번에. 
 준비 › 모델 진단 — 층·슬래브를 제대로 인식했는지 먼저 봅니다(모델은 바뀌지 않음). IFC 로 가져온 모델이면 꼭. 
 동바리 › 예시로 채우기 (슬라이드아웃) — 층마다 구역(해체 단위)과 예시 동바리. 실제 동바리는 층 입력 뷰 에서 직접 놓고 고칩니다 (v6). 결과 창 생성한 동바리 보기 = 이번에 만든 층의 동바리만 층마다 색·층별 본수로 보는 3D 뷰(뷰 설정만 바뀜). 
 날짜는 공정표 없이 직접 넣습니다 (v6): 동바리를 세운 날 동바리 › 동바리 사양 (설치일 포함), 타설한 날 타설 등록 . 
 층마다 동바리 설치 뒤 설치 검측 › 설치 검측 — 이음·높이·수평연결재·1본 하중을 한 번에. 설치 서류는 승인 › 근거 원장 1 설치검측.

 결론은 언제나 "해체 승인 요청 가능"/"존치"·"타설 요청 가능"/"타설 보류"까지입니다. 해체·타설 지시와 승인은 하지 않습니다 — 해체 여부는 감리 확인·서명을 거쳐 현장 책임자가 정합니다. 
 센서가 없어도 됩니다. 현장양생 공시체 + 기온만으로 해체 판정·한중 경고·요청서·승인 기록·타설 전 확인·공정 계획이 모두 동작합니다. 센서는 구역마다 위치 근거 (구역 안 가장 낮은 추정 강도)를 더하는 선택 기능이고, 센서가 없는 구역의 근거는 "기상 예측(센서 없음)"으로 표시되고, 뒤에 실제로 쓴 기온의 출처(기상 기록 입력 / 평년 기온 가정 )와 양생 하한 온도 가정 가 붙습니다. 기준 근거는 어느 경우든 공시체입니다. 
 주간·필요할 때 
 타임라인 › 강도 타임라인 으로 날짜를 움직여 층별 추정 강도 (참고 · 판정에 안 씀)가 14 MPa·fck 에 언제 닿을지와 그날까지의 공시체 실측을 함께 봅니다. |◀ 사건 사건 ▶| = 층 타설·추정 14 MPa·fck 도달·공시체 시험 날. 감리·발주처 설명에 그대로 씁니다.

## 서버 연동 (ServerLink.cs 머리 주석)
[타설·데이터 · 서버 연동] Vercel 현장 서버와 동기화를 켜고 끔 (v6 4단계, server/vercel/API.md). 통신·검사·CSV = Engine.FieldServer.Sync (tools/server_sync.py 1:1 이식).
   켜면 바로 한 번, 그 뒤 IntervalMin 분마다: pull → ack → push. 통신은 백그라운드 스레드 (Revit API 없음) — Revit 은 기다리지 않음.
   받아 저장한 입력이 있으면 현장 입력(LAN)과 같은 모델 반영 (FieldInput.ApplyModel: 판정 다시 계산 · 센서 표식 · 대시보드) + 강도 타임라인 다시 만듦.
   주소·키 = Windows 사용자 환경 변수 FIELD_SERVER_URL · FIELD_SYNC_KEY — 값은 화면·기록 어디에도 쓰지 않음. 결론은 엔진 판정 그대로 ("해체 승인 요청 가능" / "존치").
   휴대폰 QR (총괄 11-08 "QR 을 찍으면 Vercel 주소로 열림"): 켤 때·[서버 연동] 다시 누름 → [QR 보기] 로 ServerQrWindow — 입력(?t=FIELD_TOKEN)·층 보기(?v=)·협력업체 신고(?r=).
     토큰은 QR·이 창 글자에만 (기록·파일 이름 없음). 층 표지 QR 도 연동 중이면 서버 층 보기 주소 (FloorSignCommand).

## 배포 사실
- 현장 서버 주소: https://revit-onsite-field.vercel.app (화면: / 현장 입력, /view 층 화면, /timeline 강도·해체 타임라인, /supervisor 감리 확인). 열쇠는 QR로만 전달, 열쇠 없이 자료 API는 거부(403).
- 자동 동기화 5분 간격 (ServerLink.IntervalMin = 5).
- 판정 결론 문구는 '해체 승인 요청 가능' 또는 '존치'. 서명란(성명·서명·일시)은 비워 둠. 결정은 감리.
- 회귀 검사: tools/run_all_checks.py 40개 (Python 기준 엔진 ↔ C# 애드인 결과 바이트 동일 비교 포함).
